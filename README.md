# Ассистент невесты

Полный продуктовый прототип: React + TypeScript + Vite, Express, SQLite и серверная тестовая оплата.

## Запуск

```bash
npm install
copy .env.example .env
npm run dev
```

Откройте `http://localhost:3000`. API и hosted test checkout — `http://localhost:3001`.

Сборка и production-запуск:

```bash
npm run build
npm start
```

Проверки сквозных сценариев:

```bash
npx playwright install chromium
node verify.mjs
node verify-extra.mjs
```

`verify.mjs` проходит ветку «Есть бюджет» в варианте Б: отдельный вход и пять вопросов, затем планер, заказ, sandbox-оплату, сохранение в SQLite и мобильные карточки на 375 px. `verify-extra.mjs` проходит остальные три ветки, вариант A с восемью вопросами после входа, ограничение трёх приоритетов, фото без описания, перенос ответов в бриф, карту компромиссов и отмену платежа. Оба теста проверяют консоль и ответы 404.

## Что реализовано

- Главная с содержательной иллюстрацией и фрагментами продукта.
- Присланная схема квиза: четыре ситуации — «Есть бюджет», «Есть элементы», «Мало времени», «Не знаю, чего хочу». В варианте Б выбор ситуации является отдельным входом, затем идут ровно 5 содержательных вопросов; в варианте A добавляются ещё 3 уточнения.
- Число гостей, свободный текст, описание или до трёх фото, визуальные карточки шести локаций и трёх стилей, диапазоны, дата, мультивыбор максимум из трёх пунктов, возврат и сохранение черновика.
- Бесплатный результат без контакта, палитра, ориентир бюджета и четыре продолжения.
- Уточнение расчёта, веб-последовательность вместо имитации мессенджера, приглашение партнёра с отдельными ответами и картой компромиссов, выбор специалиста.
- Планер с этапами, статусами, действиями «Сделаю сама» / «Делегировать», добавлением задач, фильтрами, постоянной ссылкой и серверным сохранением.
- Шесть микроуслуг, бриф, контакт, checkout, заказ, повторная попытка и статусы pending / paid / error / cancelled / refunded.
- События начала, завершения и оплаты с вариантом квиза в таблице `events`.

## Визуальная система

- Природно-пудровая палитра: белый и `#EEF0E6` как основа, зелёный чай `#EAF1E4` для подложек, мох `#3F5B45` для действий, листва `#8FAE7E` для выбранных состояний и редкие пудровые акценты.
- Локальные Noto Serif 300 / 400 и Noto Sans 400 / 500 / 600 с кириллицей подключены через Fontsource; внешние font CDN не используются.
- Шестнадцать авторских иллюстраций в едином чернильно-гуашевом языке заменяют схематичные SVG. В `public/illustrations` находятся только оптимизированные WebP; исходные PNG хранятся отдельно в `../design-source/illustrations`.
- Адаптивные композиции охватывают главную, квиз, результат, планер, услугу, бриф, sandbox-оплату, заказ и партнёрскую карту. Основные проверенные ширины: 1440, 1024, 768, 390 и 360 px.
- Золото ограничено тремя приёмами: короткий блик участка границы карточки при hover, одноразовое появление линии результата / этапов и один блик успешного заказа. Используются только transform и opacity; при `prefers-reduced-motion` анимации отключены, статичные золотые элементы сохранены.

## Оплата

Без ключей используется локальный hosted sandbox. Он не собирает карты и не списывает деньги. Подтверждение приходит через отдельный server endpoint с HMAC-SHA256; только после проверки подписи заказ становится `paid`. Повторное уведомление не обрабатывает заказ повторно.

Для тестового магазина ЮKassa задайте `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в `.env`. Платёж создаётся только сервером с `Idempotence-Key`, используется hosted redirect checkout. Webhook `/api/payments/webhook` повторно запрашивает платёж у API ЮKassa и не доверяет содержимому уведомления. Для production нужен HTTPS, публичный webhook URL и отдельная проверка сетевой политики провайдера.

## Принятые допущения

- Порядок и типы вопросов реализованы по присланной схеме; её исходный текст сохранён в `kviz-variant-b-tree.md`. Прежняя реконструкция дерева больше не используется.
- Вилка бюджета — демонстрационная формула прототипа, не рыночная статистика и не смета.
- Цены и состав услуг — демонстрационные; сроки, число вариантов и доступность подрядчиков не обещаются.
- Файлы референсов представлены метаданными имени и размера; бинарное хранилище нужно подключить перед запуском.
- Один владелец проекта. Постоянная ссылка является capability URL; для публичного запуска нужны magic link, защита персональных данных и политика удаления.
- Партнёрская ссылка не имеет срока окончания в локальном прототипе; несуществующий токен обрабатывается как устаревший.
- Возврат в sandbox меняет серверный статус для проверки UX; реальный возврат через API провайдера не выполняется.

## Применённые продуктовые практики

- Zola, The Knot и Joy: план по этапам, ранняя связь бюджета и числа гостей, следующий шаг вместо перегруженного кабинета.
- Typeform-паттерн onboarding: один смысловой вопрос на экран, видимый прогресс и изменение ответов.
- Thumbtack: краткий бриф задачи перед обращения к специалисту.
- TaskRabbit: понятный результат отдельной услуги, цена и оплата в одном сквозном пути.
- Hosted checkout: объяснение тестового режима и отсутствия сбора карты рядом с оплатой; серверный статус вместо страницы ложного успеха.

## Для боевого запуска

Нужны тестовые, затем боевые ключи и получатель платежа; юридическая форма и реквизиты; оферта, политика персональных данных, правила отмены и возврата; согласованный объём каждой услуги и операционный процесс; бинарное хранилище референсов; адаптеры Telegram / WhatsApp / MAX; magic link и HTTPS. Реальные сообщения и реальные платежи в текущей локальной конфигурации не выполняются.
