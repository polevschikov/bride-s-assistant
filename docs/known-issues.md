# Известные проблемы и ограничения

## Критично перед боевым запуском

### Демонстрационная авторизация не подтверждает личность

- **Симптом:** любой корректный email создаёт клиентскую сессию; Яндекс и VK являются только подписями в интерфейсе.
- **Где:** `server.mjs`, `/api/auth/demo`; `src/Account.tsx`.
- **Причина:** осознанная заглушка текущего этапа, не OAuth-баг.

### Проекты и заказы доступны по идентификаторам

- **Симптом:** публичные `GET/PUT /api/projects/:id` и `GET /api/orders/:id` не проверяют владельца; `/api/account/link-project` принимает произвольный существующий ID.
- **Где:** `server.mjs`, соответствующие маршруты.
- **Причина:** capability URL и демонстрационная модель прототипа. До публичного боевого запуска требуется проверка владельца и защищённая привязка проекта.

### Открытый HTTP и упрощённые sandbox-операции

- **Симптом:** сайт доступен по IP без HTTPS; sandbox refund и проектные операции не являются безопасной боевой моделью.
- **Где:** Nginx, `server.mjs`, `/api/orders/:id/refund` и sandbox-маршруты.
- **Причина:** домен, HTTPS и реальные платежи отложены владельцем.

## Подтверждённый технический долг

- `npm run lint` не проходит: преимущественно `no-explicit-any`, включая рабочие интерфейсы и shadcn-шаблон. Сборка TypeScript/Vite при этом проходит.
- Полный `npm audit` на момент релиза имел 7 moderate в dev-цепочке; `npm audit --omit=dev` — 0. Не применять `--force` без отдельной задачи.
- В `server.mjs`, `content-seed.mjs`, части React и CSS используется компактная однострочная запись. Массовое форматирование затруднит review; менять стиль только отдельной задачей.
- Миграции — только `CREATE TABLE IF NOT EXISTS` и три `addColumn`; нет версионированного migration runner и автоматического rollback.
- `page_versions` хранит снимки, но UI отката нет. Для квиза и планера хранятся только текущая/черновая версии и номер версии.
- Предпросмотр реализован для страниц, но не для квиза и планера.
- Новые CMS-страницы открываются по прямому `?page=slug`; автоматического добавления в навигацию нет.
- Токены браузера находятся в `localStorage`; admin-токены находятся только в памяти процесса и сбрасываются перезапуском.
- E2E используют фиксированные порты 3000/3001, проверяют их доступность перед запуском и не могут запускаться параллельно. Прямые отдельные скрипты не имеют общей блокировки; использовать npm run check.
- GitHub CI и защита main включены 08.11.2026; текущие подтверждения — tasks/github-ci-protection.md. Автодеплоя нет. Серверный scheduled backup этим поручением не проверялся.

## Риски, требующие отдельной проверки

- **Исправлена гонка workspace E2E (08.11.2026):** два полных запуска ловили 404 /uploads/*-workspace-pixel.png. Тест удалял проверочный файл до завершения браузерного запроса миниатюры. Добавлено ожидание ответа миниатюры 200 и завершения загрузки перед удалением, проверки console/404 сохранены. Отдельный workspace и полный check после изменения прошли. При повторении исследовать новый URL/условия, не игнорировать ошибку.

- **Пустой каталог:** если скрыть все услуги, прямой `?service=...` может получить `currentService === undefined`. Искать в `src/App.tsx`, `ServiceDetail` и `Checkout`. Это гипотеза, специально не воспроизводилась.
- **MIME файлов:** сервер проверяет заявленный `mime` и размер, но не сигнатуру изображения. Искать в `/api/admin/media`, `server.mjs`.
- **Удаление данных:** связи в основном не объявлены foreign keys; ручная очистка клиентов/проектов должна учитывать связанные таблицы.
- **Отсутствие rate limiting:** публичные API и демо-вход не имеют ограничения частоты запросов.

## Нереализованные обсуждённые возможности

- Настоящие OAuth Яндекс/VK и подтверждение почты/magic link.
- Домен, HTTPS и отдельная тестовая среда.
- PostgreSQL и production-защита персональных данных.
- Реальные платежи, чеки, возвраты через провайдера и платёжные настройки кроме sandbox.
- Подключение S3 и бинарная загрузка референсов из квиза/брифа.
- Конструктор сайтов-приглашений (отложенный этап 6).
- Роли, внешние уведомления и расширенная аналитика (отложенный этап 7).
- Пополнение, вывод и оплата заказов бонусами; кошелёк пока только журнал.
- Откат опубликованных версий из админки и preview квиза/планера.

Исправленные ранее проблемы мобильного overflow кабинета и формулировки вопроса CMS в список открытых багов не входят.
