# Архитектура

## Стек и причины выбора

- **React 19 + TypeScript + Vite** — существующий интерфейс прототипа и быстрый цикл разработки.
- **Express 5 на Node.js** — единый API, sandbox checkout и раздача production-сборки без второго приложения.
- **SQLite через `better-sqlite3`** — осознанно сохранён для единственного прототипа: не требует отдельного сервиса и поддерживает консистентные backup/WAL. PostgreSQL отложен до боевого запуска.
- **Playwright** — проверка реальных пользовательских сценариев и консоли браузера.
- **Локальные Noto Serif / Noto Sans и WebP** — отсутствие внешних font/image CDN.
- **`@aws-sdk/client-s3`** — необязательный S3-совместимый адаптер; без полного набора ключей используется локальный каталог.

## Потоки и модули

```text
Браузер
  ├── публичный сайт / квиз / планер
  │      └── src/App.tsx → src/SiteHome.tsx, src/data.ts
  ├── кабинет `?account=1`
  │      └── src/Account.tsx → /api/auth/demo, /api/account, /api/projects
  └── админка `?admin=1`
         └── src/admin/* → /api/admin/*

Express `server.mjs`
  ├── /api/public/config → опубликованные страницы, услуги, квиз, настройки
  ├── /api/projects, /api/partners → проект и совместные ответы
  ├── /api/orders, /api/payments, /api/sandbox → заказы и тестовая оплата
  ├── /api/auth, /api/account → демо-сессии и кабинет
  ├── /api/admin → CMS, заявки, клиенты, услуги, медиа и настройки
  ├── content-seed.mjs → первичное наполнение через INSERT OR IGNORE
  ├── storage.mjs → локальные файлы или S3
  └── SQLite + production `dist/`
```

Маршрутизация интерфейса реализована состоянием React и query-параметрами, а не таблицей маршрутов: `?admin=1`, `?account=1`, `?page=slug`, `?preview=1`, `?project=id`, `?service=id`, `?order=id`, `?partner=token`.

- Vite development: порт `3000`, proxy `/api`, `/sandbox`, `/uploads` на `3001`.
- Production: Express слушает `3001`, раздаёт `dist` и `/uploads`; Nginx проксирует HTTP 80 на Express.
- CMS-черновик страницы доступен через `?page=slug&preview=1` только с токеном администратора из `localStorage`.

## База данных

Все таблицы создаются в `server.mjs` через `CREATE TABLE IF NOT EXISTS`.

| Группа | Таблицы и назначение |
|---|---|
| Проекты | `projects` — вариант, ответы, результат, задачи, контакт, `client_id`, `quiz_version`; `partners` — token и ответы партнёра |
| Заказы | `orders` — снимок названия/цены услуги, бриф, контакт, статус, `client_id`; `payments` — платёжные попытки и raw payload |
| Работа администратора | `order_notes` — внутренние комментарии; `order_history` — история статусов |
| События | `events` — начало/завершение квиза и платёжные события |
| Клиенты и вход | `clients` — профиль; `auth_identities` — демо-привязки email/yandex/vk; `client_sessions` — bearer-сессии с истечением |
| Каталог | `services` — цена, состав, изображение, видимость и порядок |
| CMS | `pages` — текущая и черновая версии; `page_versions` — опубликованные снимки страниц |
| Квиз и планер | `quiz_definitions`, `planner_templates` — опубликованные и черновые JSON + номер версии |
| Настройки и файлы | `settings` — key/value; `media` — URL, storage key, MIME, размер и alt |
| Кошелёк | `wallet_transactions` — только журнал операций; баланс вычисляется суммой |

JSON хранится текстом и парсится при чтении. Идентификаторы генерируются случайно с префиксами (`p_`, `o_`, `c_`, `media_` и другими). Время хранится в ISO UTC.

## Миграции и начальное наполнение

Отдельного migration runner нет. При старте:

1. Создаются отсутствующие таблицы.
2. `addColumn` добавляет только `projects.client_id`, `projects.quiz_version`, `orders.client_id`, если их нет.
3. `INSERT OR IGNORE` наполняет услуги, главную, квиз, планер и настройки, не перезаписывая существующий контент.
4. Включены `journal_mode = WAL` и `foreign_keys = ON`, но большинство связей не объявлено внешними ключами.

Перед любым изменением схемы обязателен backup через `db.backup(...)`. Команда находится в `docs/setup.md`. Откат миграций не автоматизирован.

## Авторизация и хранение

- Администратор: один `ADMIN_ACCESS_CODE`; bearer-токены в памяти процесса на 7 дней, без ролей. Перезапуск очищает административные сессии.
- Клиент: локальная демо-сессия на 30 дней в SQLite; email, Яндекс и VK не вызывают внешние сервисы.
- Токены браузера хранятся в `localStorage`.
- Медиа: JPG/PNG/WebP до 8 МБ; JSON limit Express — 14 МБ.
- Локальные файлы production: `/var/lib/bride-assistant/uploads`.
- S3 включается только при одновременном наличии endpoint, bucket и пары ключей.

## Внешние зависимости

- GitHub — исходный код, ручной deploy через `git pull`.
- REG.RU — VPS, Nginx, systemd и SQLite; DNS-панель существует, домен не подключён.
- REG.RU S3 — хранилище заявлено владельцем, но ключи в приложении не настроены.
- ЮKassa — серверный код существует, реальные ключи не установлены; активен локальный HMAC sandbox.
- Внешние OAuth, почта, аналитика и мессенджеры не подключены. CI-конфигурация подготовлена локально, удалённо не проверена; автоматического деплоя нет.
