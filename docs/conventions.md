# Соглашения проекта

## Рамка изменений

- Выполнять только конкретную задачу владельца; сопутствующие улучшения сначала предлагать отдельно.
- Обновлять `docs/` в каждой задаче: статус, архитектуру, решения, проблемы и доступы при их изменении.
- Не менять production, DNS, платежи, S3, права и секреты без явного запроса.
- Не коммитить `.env`, пароли, токены, ключи, дампы SQLite, пользовательские загрузки и `test-output`.

## Код и файлы

- JavaScript — ESM (`"type": "module"`); серверные модули — `.mjs`, интерфейс — `.tsx`/`.ts`.
- Сохранять стиль конкретного файла. В рабочих модулях много компактных однострочных конструкций; не делать массовое форматирование вместе с функциональными изменениями.
- Имена React-компонентов — PascalCase; функции и переменные — camelCase; ключи API и JSON сохраняются в существующем snake_case там, где это формат данных.
- Пользовательские ошибки и статусы — на русском. Не менять текст квиза без проверки исходной схемы `kviz-variant-b-tree.md`.
- Новые публичные состояния выбираются существующим способом через query-параметры и состояние React; не внедрять вторую систему маршрутизации без решения владельца.
- Не подключать новые пакеты для уже существующей функциональности без необходимости.

## API и данные

- SQL — только prepared statements с параметрами; не подставлять пользовательский ввод в SQL.
- JSON-поля сериализуются/парсятся существующими helpers. Даты — ISO UTC, ID — случайные строки с префиксом.
- Ошибки API возвращаются как JSON `{error: "…"}` с подходящим HTTP-статусом.
- Опубликованный контент и черновик разделять. Изменения появляются на сайте только после publish.
- Уже созданный заказ сохраняет снимок названия и цены услуги.
- Изменение шаблона планера не перезаписывает существующие проекты.
- Новая версия квиза не переписывает сохранённые ответы.
- Баланс не редактируется числом напрямую: только записи `wallet_transactions`; отрицательный итог запрещён.
- Удаление используемой услуги заменяется скрытием. Главную страницу удалить нельзя.
- Перед изменением схемы или production-данных обязателен SQLite `db.backup(...)`.

## Интерфейс

- Сохранять Noto Serif для заголовков и Noto Sans для рабочего текста, природную палитру и локальные шрифты/иллюстрации.
- Публичные стили — `src/index.css`; админка/кабинет/CMS — `src/workspace.css`.
- Не заменять продуктовые компоненты стандартной темой shadcn/ui. Библиотека `src/components/ui` является исходным шаблоном, а не обязательным стилем продукта.
- Обязательны клавиатурная доступность, видимый focus, русские alt/labels, отсутствие горизонтального скролла страницы на 390 px и отсутствие неработающих кнопок.
- Медиа: JPG/PNG/WebP до 8 МБ. Для содержательных изображений указывать alt.

## Проверки и Git

- Перед отправкой кода: `npm run build`, затем последовательно `node verify.mjs`, `node verify-extra.mjs`, `node verify-workspace.mjs` для затронутых сценариев.
- Проверять console errors и 404. Не заявлять проверку, которая фактически не выполнялась.
- Не выдавать `npm run lint` за зелёный, пока это не подтверждено новым запуском.
- История использует короткие английские imperative commit messages: `Add ...`, `Clarify ...`, `Record ...`.
- Коммиты маленькие и по одной задаче. Рабочая ветка — `main`, CI/CD нет.
- Не удалять шаблонные/временные файлы из списка `project-map.md` без отдельного разрешения.
