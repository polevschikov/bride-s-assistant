# Проверки проекта

Тесты нужны для подтверждения исправлений и защиты уже работающих сценариев. Не обещают отсутствие всех ошибок и не заменяют проверку требований/дизайна. Новые тесты добавлять по риску и к реальным исправлениям; не измерять качество количеством тестов.

Команды из app/ на Node.js 24 с установленными зависимостями `npm ci`:

| Команда | Назначение |
|---|---|
| `npm run build` | TypeScript и production-сборка |
| `npm test` | Локальный API, авторизация, сохранность после restart, SQLite backup |
| `npm run test:e2e` | Последовательно три существующих verify-скрипта |
| `npm run check` | Сборка, API и три E2E; останавливается при ошибке |
| `npm run lint` | Отдельная диагностика известного долга, сейчас не обязательный зелёный gate |

Для браузерных скриптов нужен Chromium Playwright: `npx playwright install chromium`. В Linux CI — `npx playwright install --with-deps chromium`. Тесты автоматизированы в коде; ручные браузерные проверки агент выполняет через выбранный пользователем Chrome. Рабочий сайт не является целью этих тестов.

## Покрытие

- verify.mjs: ветка B «Есть бюджет», пять вопросов, планер, sandbox-оплата, запись в БД, часть мобильного интерфейса.
- verify-extra.mjs: остальные ветки и A, максимум приоритетов, метаданные фото, партнёр и отмена оплаты.
- verify-workspace.mjs: кабинет, админка, клиенты/заказы/бонусы, CMS, публикация/черновики, медиа и мобильные экраны.
- tests/api.test.mjs: health, запрет административного API без токена, сохранность проекта после перезапуска, читаемая резервная копия SQLite с сохранённой записью.

Нет подтверждённого полного покрытия: настоящие OAuth/платежи/S3, все негативные API-сценарии, конкурентные изменения, все миграции/совместимость версий, полная визуальная приёмка и серверное восстановление. Обсуждённые production-интеграции пока заглушки; не тестировать их как реализованные.

## Изоляция и результаты

E2E создают отдельные test-output/*.db и каталоги медиа; запуск последовательный на 3000/3001. Перед запуском проверяется свободный порт: чужие процессы не останавливать. Vite не должен автоматически перейти на другой порт. dotenv, ключи оплаты и S3 из окружения отключены в тестовом env. Не запускать два набора одновременно и не задавать рабочие URL/данные. Прямой запуск verify также проверяет порты.

`npm run check` использует локальную блокировку и сохраняет test-output/check-summary.json с командами, кодами выхода, временем и путями к check-N.log каждого этапа. При таймауте останавливает дерево своих процессов. Это артефакт текущего запуска, не постоянный сертификат. При зависании проверить свои дочерние процессы и устаревшую блокировку, не удалять lock работающего запуска. Проверки могут создавать временные файлы и скриншоты; они исключены из Git.

GitHub Actions конфигурация .github/workflows/check.yml подготовлена для PR и push main, без деплоя и секретов. Пока изменения не отправлены и запуск не наблюдался, удалённый CI считается непроверенным. Branch protection отдельно не включён. Локальные результаты заносятся в состояние текущей задачи.
